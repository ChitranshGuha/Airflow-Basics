1. The Easy Route: Built-in Email AlertsAirflow has native email support built right in. If your infrastructure administrator has configured an SMTP server in your airflow.cfg file, you don't even need to write a custom callback. You just add three parameters to your default_args:Pythondefault_args = {
    'owner': 'platform_team',
    'retries': 2,
    # Native email configuration
    'email': ['data-team@mycompany.com'],
    'email_on_failure': True,
    'email_on_retry': False 
}
Any task that fails in this DAG will automatically send an email with the task ID, execution time, and a direct link to the logs.2. The Custom Route: Slack Alerts (Callbacks)To send alerts to modern tools like Slack, Microsoft Teams, or PagerDuty, you write a custom function and attach it to the on_failure_callback parameter.When a task fails, Airflow passes the "context" dictionary (the same one that holds your Jinja {{ ds }} variable and the XCom ti object) into your function so you can extract exactly what went wrong.Here is how you set up a Slack failure alert:Pythonfrom airflow.providers.slack.hooks.slack_webhook import SlackWebhookHook

# 1. Define the callback function
def send_slack_alert(context):
    # Extract details from the failed task's context
    task_id = context.get('task_instance').task_id
    dag_id = context.get('task_instance').dag_id
    log_url = context.get('task_instance').log_url
    
    message = f"🚨 Task *{task_id}* failed in DAG *{dag_id}*!\nCheck logs here: {log_url}"
    
    # 2. Send the message using a Hook (requires a Slack connection saved in the UI)
    slack_hook = SlackWebhookHook(slack_webhook_conn_id='slack_alerts_connection')
    slack_hook.send_text(text=message)

# 3. Attach it to your default_args so it applies to every task
default_args = {
    'owner': 'platform_team',
    'on_failure_callback': send_slack_alert
}
